# 模块系统

> 对标 [Python Modules](https://docs.python.org/zh-cn/3.16/reference/import.html)
>
> Tanex Script 模块系统基于**文件/文件夹/编译库**三种形式，通过表达式符号 `import` / `->` 引入。模块加载为 `Library` 类型句柄(`import`)或直接展开到当前作用域(`->`)。

---

## 1. 模块概念与文件后缀

| 后缀/形式 | 名称 | 含义 | 典型用途 |
|-----------|------|------|----------|
| `.tsuc` | Tanex Script Uncompiled Code | 源码文件，文本格式 | 开发编写、分发源码 |
| `.tscc` | Tanex Script Compiled Code | 编译产物，JSON AST | 解释器直接加载执行，启动快 |
| `.tscl` | Tanex Script Compiled Library | 编译库，二进制打包多 `.tscc` | 标准库分发、大型库发布 |
| 目录/ | 库文件夹 | 含 `main.tsuc` 等的目录 | 源码库开发、多文件组织 |

**编译流向**：
```
.tsuc (源码) --编译器--> .tscc (JSON AST)
.tscc 可直接运行
多个 .tscc --打包器--> .tscl (二进制库)
库文件夹 --编译器--> .tscl
```

---

## 2. `import` 与 `->` 语义对比

| 特性 | `import expr` | `-> expr` |
|------|---------------|-----------|
| **产生句柄** | ✅ `Library` 类型常量 | ❌ 无句柄 |
| **作用域污染** | 无(仅句柄绑定到标识符) | 是(文件所有顶层声明展开到当前作用域) |
| **命名引入** | ✅ `import expr = *name` | ❌ 不支持 |
| **列表批量** | ✅ `import [e1,e2] = [*n1,*n2]` | ✅ `-> [e1,e2]`(不支持命名) |
| **动态路径** | ✅ 运行时求值表达式 | ✅ 运行时求值表达式 |
| **注解隔离** | ✅ 库独立注解空间 | ⚠️ 注解合并到当前顶层 `annotations` |
| **典型场景** | 标准库、大型库、需隔离命名空间 | 小工具库、脚本快速引用、REPL 探索 |

**核心区别**：`import` 保持**命名空间隔离**，`->` 进行**作用域合并**。

## 3. 引入形式完备

### 3.1 单条引入

```tanex script
import "standard";           # 绑定到标识符 standard
-> "standard";               # 展开标准库所有顶层声明
import "lib.tsuc";           # 路径为字符串字面量(预编译解析)
import "lib" + suffix;       # 路径为动态表达式(运行时求值)
```

### 3.2 命名引入(仅 `import`)

```tanex script
import "maths.tsuc" = *m;        # 库实例地址引用绑定到 m
import "lib_" + suffix = *mylib; # 动态路径 + 命名
# -> "lib" = *m;  # ❌ 报错：-> 不支持命名引入
```

- `=` 后**必须**为 `*name` 形式(地址引用绑定)，裸标识符 `name` 报错
- 绑定的标识符为**常量**(`***` 语义)，不可重新赋值

### 3.3 列表批量引入

```tanex script
import ["maths", "random"];           # 分别绑定到 maths、random
import ["maths", "random"] = [*m, *r]; # 绑定到 m、r
-> ["maths", "random"];               # 依次展开两个文件
# -> ["a", "b"] = [*x, *y];  # ❌ 报错：-> 不支持列表命名
```

- 路径列表每个元素可为任意表达式，运行时逐个求值
- 路径列表与名称列表(若存在)长度**必须一致**，否则报错
- 路径列表不能为空

## 4. 路径解析算法

### 4.1 预编译阶段(静态字符串字面量)

操作数为**字符串字面量**(单条或列表元素)：
1. 解析相对/绝对路径(相对路径基于当前文件目录或库搜索路径)
2. 若为 `.tsuc`：调用编译器生成 `.tscc`，写回绝对路径到 AST
3. 收集依赖图，拓扑排序编译
4. 歧义消除见下

### 4.2 运行时阶段(动态表达式)

操作数为**非字面量表达式**(拼接、变量、函数调用等)：
1. 保留 import token 序列原样输出到 AST
2. 运行时求值表达式得字符串路径
3. 调用 `_load_library_module` 动态加载(复用标准库解析逻辑)
4. 不进行静态依赖收集

### 4.3 歧义消除规则

| 情况 | 处理 |
|------|------|
| 工作目录下同名多内容(`lib/`、`lib.tsuc`、`lib.tscc`、`lib.tscl`) | 报错，提示加后缀避免歧义：文件夹加 `/`、文件加后缀名、或写绝对路径 |
| 同名文件夹与 `.tscl` 同时存在 | 裸名导入 `.tscl`；要导入文件夹需加 `/`(如 `"lib/"`) |
| 同名 `.tsuc` 与 `.tscc` 同时存在 | `.tscc` 视为编译产物，**不触发歧义**，优先 `.tscc` |
| 引入 `"standard"` 但本地也有 `standard` | 报错歧义，提示用绝对路径区分(标准库在安装目录 `run/` 下) |
| 导入后发现同名标识符已存在 | **覆盖**，并给予**警告** |
| 库内部同名内容重复(如 `a.tscc` 与 `a.tsuc` 同在库中) | 报错 |

### 4.4 标准库优先级

- 裸名 `"standard"` **优先解析为安装目录标准库**(`run/standard.tscl` 或 `run/standard/`)
- 本地同名库需用绝对路径或 `./standard` 显式指定

## 5. 库初始化顺序

1. **依赖拓扑排序**：预编译阶段收集所有静态 `import` 依赖，构建 DAG，按拓扑序编译
2. **循环依赖检测**：静态依赖图有环 → 编译期报错“循环依赖”。动态 `import` 运行时可能形成环，运行时检测并报错
3. **库加载执行**：
   - 打开 `.tscc`/`.tscl`，解析 AST 语句列表
   - 在**当前地址空间和全局作用域**中逐条执行库语句(与用户代码共享环境)
   - 库顶层 `$`/`return`：返回整数作为库加载结果(通常忽略)，非整数报错
4. **main 入口逻辑**(库文件夹/`.tscl`)：
   - 若库含 `main.tsuc`/`.tscc`：执行该文件作为库初始化
   - 嵌套 `main/` 目录：取**最深层** `main/main/.../main.tsuc`
   - 无 main 文件：不报错，但需用户手动引入库内内容
5. **嵌套库展开**：库中包含其他 `.tscl` 时，**不直接写入**编译产物，而是将内部文件**重新写入**外层 `.tscl`(扁平化)

## 6. 可见性控制：`public`

### 6.1 语法

```tanex script
*** public = ["func1", "Type1", "CONST1"];
```

- 仅在**文件级**(模块文件顶层)有效
- 值为 `List`，元素为允许外部访问的标识符字符串

### 6.2 行为

| `public` 声明 | 效果 |
|---------------|------|
| 未声明 | 默认**所有**顶层标识符公开(可被 `import` 访问) |
| 声明空列表 `[]` | **无内容公开**(完全私有) |
| 声明列表 | **仅列出标识符**可被外部 `import` 访问，其余不可见 |

- `->` 引入**不受 `public` 限制**(直接展开所有顶层声明)
- 库文件夹 `main.tsuc` 中的 `public` 控制整个库的导出面

### 6.3 示例

```tanex script
# lib.tsuc
*** internal_helper = [*x] => { $ x + `1; };
*** public_api = [*x] => { $ x * `2; };
*** public = ["public_api"];  # 仅导出 public_api
```

```tanex script
# 用户代码
import "lib" = *lib;
lib.public_api(`5`);   # => `10 ✅ #;
# lib.internal_helper(`5`);  # ❌ 报错：成员不存在
```

## 7. 库注解隔离机制

- `import "lib" = *h;` 时，`lib` 的编译产物 `annotations` 字段写入**独立注解空间**(以库句柄为键的子表)
- 顶层 `?? name` **不**包含库内部注解
- 跨库读取：`?? lib.member` 访问库独立空间中的 `member` 注解
- 文件级注解：`?? lib` 读取库的 `annotation` 字段

```tanex script
# lib.tsuc
@ my_func # 库内函数文档 #;
*** my_func = [] => { $ `1; };

# 用户代码
import "lib" = *lib;
?? my_func;        # => none (顶层无此注解) #;
?? lib.my_func;    # => "库内函数文档" ✅ #;
?? lib;            # 文件级注解
```

- `-> "lib";` 引入时：库注解**合并**到当前顶层 `annotations`(键冲突覆盖警告)

## 8. REPL 内置常量

REPL 会话与脚本运行同理注入以下常量：

| 常量 | 脚本运行值 | REPL 值 | 说明 |
|------|------------|---------|------|
| `path` | 当前脚本绝对路径 | `none` | REPL 无脚本文件 |
| `program_path` | 解释器安装目录 | 同左 | 如 `C:/Program Files/TanexScript` |
| `args` | 命令行参数列表 | `[]` | REPL 通常为空 |

**用途**：`import program_path + "/lib/extra.tsuc"` 在 REPL 与脚本中均可工作。
