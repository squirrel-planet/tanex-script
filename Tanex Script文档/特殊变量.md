# 特殊变量

类型对象上有一部分成员名具有特殊运行时含义，统称**特殊变量**（特殊成员）。普通成员只存储数据；特殊变量会被运行时识别，参与类型的行为控制。这些名字是运行时保留的，不应当作普通成员使用。

---

## 特殊变量总览

| 类别 | 特殊变量 | 作用 |
| ---- | -------- | ---- |
| 类型元信息 | `inherit` | 继承目标 |
| 构造与转换 | `initialize` | 构造器，创建实例时调用 |
| 构造与转换 | `boolean` | 真值转换，用于条件判断 |
| 构造与转换 | `string` | 字符串转换，用于 `<<` 输出 |
| 构造与转换 | `include` | 存在判断，用于 `in` 运算符优先判定 |
| 构造与转换 | `index` | 索引访问，用于 `a[b]` 与 `in` 兜底遍历 |
| 算术 | `addition` `subtract` `multiply` `divide` `exactly_divisible` `modulo` `power` | 七个算术运算符 |
| 一元 | `positive` `negative` | 一元正负号 `+n` `-n` |
| 比较 | `greater` `less` `greater_equal` `less_equal` `equal` `not_equal` | 比较运算符（未定义时由解释器兜底） |
| 比较 | `compare` | 三路比较，作为比较运算符的最后兜底 |
| 行为控制 | `addable` | 可新增标记 |
| 行为控制 | `external_read_only` | 外部只读标记 |
| 文件控制 | `public` | 当前文件可引用内容 |

---

## addable —— 可新增标记

**定义**：`addable` 是一个布尔标记，控制某个类型是否允许在外部新增成员。

**默认行为**：类型对象上没有 `addable` 成员时，视为允许新增——外部代码可以在该类型上添加新成员。

**声明行为**：在类型上声明 `addable` 并赋假值后，该类型进入"封闭"状态，外部再向它新增成员会报错；赋真值则保持开放。

**机制**：向类型新增成员时（成员名在该类型上尚不存在），运行时先检查类型是否声明了 `addable`：

- 未声明 `addable` → 允许新增。
- 已声明且值为真 → 允许新增。
- 已声明且值为假 → 报错"类型不可新增成员"。

**用途**：让核心/基础类型封闭，防止用户代码随意扩充，保持类型契约稳定。

---

## external_read_only —— 外部只读标记

**定义**：`external_read_only` 用于标记某个成员为"外部只读"，即仅类型内部可写、外部只能读取。

**机制**：该标记与 `addable`、`inherit` 一样，属于"类型自身管理"的特殊变量，在继承复制时被跳过——父类型上名为 `external_read_only` 的成员不会复制给子类型。

**设计意图**：保护受约束的状态，防止外部代码或子类型绕过类型内部管理擅自修改；由于这类成员不随继承传递，需要时由子类型显式声明。

## 比较特殊成员（greater / less / greater_equal / less_equal / equal / not_equal）

定义 `>`、`<`、`>=`、`<=`、`==`、`!=` 六个比较运算符：

| 特殊成员 | 对应运算符 |
| -------- | ---------- |
| `greater` | `>` |
| `less` | `<` |
| `greater_equal` | `>=` |
| `less_equal` | `<=` |
| `equal` | `==` |
| `not_equal` | `!=` |

**兜底调用**：比较特殊成员之间**不相互派生**——不要求在类型内部写出 `!(less() && equal())` 之类的组合。当运算符对应的特殊成员未定义时，由解释器在**函数调用层**以"兜底调用"方式补齐：调用相关特殊成员时，给控制函数调用的方法附加一个参数，标记"本次调用是给另一个方法兜底的"，由解释器据此组合结果：

- `greater` 未定义 → 兜底调用 `less` 与 `equal`，结果取反组合（`!(a<b || a==b)`）。
- `less` 未定义 → 兜底调用 `greater` 与 `equal`，结果取反组合。
- `greater_equal`（`>=`）未定义 → 兜底调用 `less`，结果取反（`!less`）。
- `less_equal`（`<=`）未定义 → 兜底调用 `greater`，结果取反（`!greater`）。
- `equal` 未定义 → 兜底调用 `not_equal`，结果取反。
- `not_equal` 未定义 → 兜底调用 `equal`，结果取反。

**机制**：派生逻辑集中在解释器的函数调用机制中，不要求类型内部互相调用；被兜底调用的方法通过调用参数上的标记知道自己处于兜底场景，避免无限递归。因此只定义 `less` 与 `equal`，即可获得全部比较能力。

## compare —— 三路比较特殊成员

**定义**：`compare` 是一个三路比较特殊成员，语义类似 C++ 的三路比较运算符 `<=>`：接收另一个值，返回一个**整数或数字**，通过符号表达两个值的序关系：

| 返回值符号 | 含义 |
| ---------- | ---- |
| 负数 | 左值小于右值 |
| 零 | 左值等于右值 |
| 正数 | 左值大于右值 |

**返回值约束**：`compare` 的返回值**只能是 `integer` 或 `number`**。返回其他类型时，解释器会报错"compare 特殊成员的返回值必须是 integer 或 number"。

**兜底顺序**：当某个比较运算符（如 `>`）求值时，解释器按以下顺序查找：

1. 该运算符的直接特殊成员（如 `greater`）；
2. 由其他比较特殊成员组合的[兜底调用](#比较特殊成员greater--less--greater_equal--less_equal--equal--not_equal)（如 `>` 由 `less` 与 `equal` 取反组合）；
3. `compare` 三路比较兜底；
4. [对象同一性比较](#对象同一性兜底)（最后兜底）。

只有前两种机制所需的特殊成员都缺失时，才会尝试 `compare`。调用后按运算符把符号解释为布尔结果：`>` 要求正数、`<` 要求负数、`>=` 要求非负、`<=` 要求非正、`==` 要求零、`!=` 要求非零。若类型连 `compare` 也没有，则落入对象同一性比较。

**用途**：类型只需要实现一个 `compare`，即可在未定义其他比较特殊成员时获得全部六个比较运算符的能力。

## 对象同一性兜底

**定义**：当类型上没有任何可用的比较机制（直接特殊成员、组合兜底、`compare` 均缺失）时，比较运算符不再报错，而是退化为**对象同一性比较**。

**机制**：以对象是否为同一个为判断依据：

- `==`：两个值是同一个对象才为真；
- `!=`：两个值不是同一个对象才为真；
- `<=`、`>=`：同一个对象才为真；
- `<`、`>`：恒为假。

**说明**：`type_type` 不再内置 `equal` 特殊成员，类型也没有默认的比较行为；一切类型在没有声明任何比较特殊成员时，比较都落在同一性兜底上。这保证了任意两个值都能参与比较而不报错，只是没有特殊成员时只能区分"是否同一个对象"。

## positive / negative —— 一元正负号特殊成员

**定义**：`positive` 与 `negative` 是处理一元正负号 `+n`、`-n` 的特殊成员，接收自身、返回运算结果。

**机制**：求值 `+n` 时，若 `n` 是用户定义类型的实例，解释器查找该类型的 `positive` 特殊成员：

- 定义了 → 调用它，结果作为 `+n` 的值；
- 未定义 → 内置数值类型（`number`、`infinite_type`、`nan_type`）保持内置行为，其他类型报错"类型不支持一元正号"。

求值 `-n` 时同理查找 `negative`：

- 定义了 → 调用它，结果作为 `-n` 的值；
- 未定义 → 回退到内置一元负号（对 `number`、`infinite_type`、`nan_type` 生效），其他类型报错"不支持一元负号"。

**用途**：让用户定义的类型可以自定义 `+n`、`-n` 的语义（如取相反向量、增/减 1 等）。

---

## public —— 可引用内容控制

**定义**：`public` 是一个文件级的特殊变量，控制当前文件中哪些内容可以被外部引用（作用类似 `__all__`）。

**声明**：通过 `*** public` 声明，值为一个名字列表，列出允许外部引用的标识符。

**机制**：未声明 `public` 时，当前文件的内容按默认规则可被外部引用；声明后，只有 `public` 列表中列出的名字对外可见，其余内容不可被外部访问。

**用途**：控制库/文件的对外接口面，只暴露需要暴露的内容，隐藏内部实现细节。

---

## 继承复制规则

子类型继承父类型时，父类型的成员会**全量复制**到子类型，但以下三个特殊变量**不参与复制**：

- `addable`
- `external_read_only`
- `inherit`

原因是它们描述的是类型自身的行为控制与元信息，不应随继承自动传递给子类型；子类型若需要这些控制，应自行显式声明。
