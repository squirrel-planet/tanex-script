# import 逻辑

`import`(`->` 语句)用于引入Tanex Script文件(.tsuc)、Tanex Script已编译文件(.tscc)、文件夹(Tanex Script库格式的文件夹)或Tanex Script库(.tscl)。

`->` 是一个独立语句，在**预编译阶段**处理：预编译器解析出导入目标并编译为一个 `import` 语句节点写入 AST（因此 import 节点存在于编译产物中，运行时执行）。它不是一个运算符，不能用于表达式内部。

引入一个内容，会把它的名字处理为一个 Tanex Script 标识符，然后把一个 `library` 类型的值填入该标识符（该标识符为**常量**，不可再赋值），值内部存储导入的内容。

库的内容**不会**被展开到全局作用域，只能通过该 `library` 句柄访问，如 `standard.output(...)`、`standard.type()`；直接使用 `output(...)`、`type()` 会因"变量未定义"报错。

库的**注解**同样隔离：导入时写入该库独立的注解空间，读取需通过 `?? 库.成员`（如 `?? standard.for`），不会平铺进顶层注解表。

引用 `"standard"` 时，自动引用标准库。

命名引入：`-> "*" = name`，把一个内容引入，并把内容存储进规定的标识符里。

## 列表批量引入

可以在一条语句中引入多个内容：

- `-> ["a", "b"];`：分别引入 `a`、`b`，等价于 `-> "a"; -> "b";`，默认以路径名为标识符。
- `-> ["a", "b"] = [x, y];`：引入 `a`、`b` 并分别存储进 `x`、`y` 标识符。

要求：

- 路径列表与名称列表（若存在）的长度必须一致，否则报错。
- 路径列表不能为空。
- 路径列表的每个元素必须是字符串文件路径；名称列表的每个元素必须是标识符。
- 同一路径同一名称只导入一次；同一路径不同名称（如重复引入同一内容）允许，运行时复用已加载的内容。
- `import` 与 `->` 完全等价，即 `import ["a", "b"] = [x, y];` 写法同样有效。

有一些引用的情况需要考虑：

1. 引入 "lib"，但工作目录下有多个匹配"lib"的可引用内容(如 ./lib/ ./lib.tsuc ./lib.tscc ./lib.tscl)。
解决方法: 报错，说明若有多个可引用的内容，可以加后缀避免歧义(文件夹加`/`，文件加后缀名)，也可以直接写绝对路径。
编译产物不算独立内容，不会触发歧义: `.tscc` 是同名 `.tsuc` 的编译产物，`.tscl` 是同名文件夹的编译产物。
同名文件夹与 `.tscl` 同时存在时，裸名导入 `.tscl`；要导入文件夹，需加 `/` 后缀(如 `"lib/"`)。

2. 类似(1)的情况，引入"standard"，但同时有多个可引用内容，可以引用标准库，可以引用工作目录下的内容，报错提示需要绝对路径(标准库在 Tanex Script 安装目录下)。

3. 引入内容后发现有同样标识符的内容，就覆盖它，然后给予警告。

4. 如果引入的内容包含多个相同标识符的内容(如，用户尝试引入lib，但 lib/ 里同时有 a.tscc, a.tsuc 两个同样的内容，引入后会变为两个相同标识符的 a)，报错。

5. 若导入内容的名字是一个不可转标识符的内容，报错，提示要命名引入 `import "*" = name`。
