# interpreter — AST 解释器

递归遍历编译后的 AST 节点，执行对应的语言操作。是运行时的核心。

---

## 控制流机制

语言用三种特殊行为实现控制流，运行时以内部信号的方式在求值过程中传播：

- **`break`**：跳出当前循环，只在 `$$` 循环内生效。
- **`return` / `$`**：返回，携带一个值。被函数调用处捕获，作为调用结果；代码块内遇到则提前结束代码块。
- **`<-`**：报错，携带一个错误值。被 `|` 尝试结构捕获。

**机制**：这三种行为不是程序错误，只在各自对应的结构里生效。真正的错误（变量未定义、成员不存在、类型不支持某操作等）会向上报出，由运行入口处理；用户代码可以用 `|` 尝试结构拦截它们。

## 辅助机制

### 类型解析

给定一个类型名，在作用域中查找这个名字，拿到地址后在地址空间中取出值。如果这个值是类型对象就返回它，否则返回空。引导库注册的内容、用户定义的内容（如 `number`、`string`、`list`）都通过它找到对应的类型对象。

### 代码块执行

接收一个 AST 节点。如果是代码块，就依次执行其中的每一条语句，返回最后一条的结果；执行中遇到返回则立即返回其携带的值。如果不是代码块，就正常求值。

**机制**：这是"代码块作为一等公民"的落地。`if`、`for`、`while`、`cycle` 等控制函数接收的代码块参数都靠它执行；代码块里出现 `$ 表达式` 时提前结束也由它处理。

### 真值判定

判断一个值在布尔上下文中的真假。规则按顺序如下：

1. 原类型 `integer`：非 0 为真。
2. 实例：如果它的类型注册了 `boolean` 特殊成员，就调用它拿到结果；没有则默认为真。
3. 类型对象：默认为真。
4. 其它值（代码块、地址值）：默认为真。

**机制**：真值判定是一切"条件"语义的基础——`!`、三目 `?:`、`&&`、`||` 以及条件函数都靠它判断真假。类型通过注册 `boolean` 特殊成员自定义自身真假：`none_type` 注册了恒返回假的 boolean，所以 `none` 在条件里恒为假；`boolean` 类型则把存储的 0/1 直接作为真假。

### 引号剥离

把字符串、数字字面量两端的引号去掉。例如 `"hello"` 变成 `hello`，`'3.14'` 变成 `3.14`。

### 赋值目标解析

接收赋值语句左侧的 AST 节点，解析出要往哪里写值。按节点类型分别处理：

1. **普通名字**：在当前作用域中查这个名字，返回它关联的地址。
2. **成员访问**（`a.b`）：先求值左边的表达式拿到对象，再在对象的成员中查找右边的名字。找到了就返回成员地址；没找到且左边是实例，分配一个新地址给这个成员并返回；左边是类型且该类型允许新增成员，也分配新地址。
3. **下标访问**（`a[b]`）：这是取地址场景。先求值左右表达式，如果左边是实例：类型有索引方法就调用它拿到结果，结果是地址值就返回其内部地址，结果是带 `value` 成员的实例就返回该成员地址；没有索引方法但有构造器，就调用构造器拿结果；否则报错。
4. **一元声明符**（`*name`、`**name`、`***name`）：在当前作用域分配新地址返回。`***name` 还会标记常量；`***类型.成员名` 则在类型对象上分配新成员地址并标记常量。

### 注解表

解释器维护一张注解表（`annotations` 字典），记录编译阶段收集的[注解](../../Tanex%20Script%20文档/注解.md)：键为目标标识符，值为注解内容字符串。

**机制**：编译结果顶层携带 `annotations` 字段。解释器在加载引导库和用户文件时，会把各自编译结果里的 `annotations` 合并进这张表；运行到一元运算符 `?? n` 时从表中取 `n` 对应的内容构建字符串返回，找不到则返回 `none`。注解表是"编译期元数据在运行时的落点"——注解不参与求值，只被 `??` 按需读取。

## 求值（按 AST 节点类型分发）

### 字面量

- **integer**：AST 记录的是字符串形式的数字，直接作为整数值返回。
- **number**：去掉引号后按"整数部分 front + 小数部分 back + 小数位数"拆分存储。见[引导库数字机制](bootstrap.md#数字类型)。
- **string**：逐字符构建链表，每个字符的 Unicode 码点存入链表节点，字符串的 `data` 成员持有这条链表。
- **none / nan / infinite**：`none` 返回全局唯一空值；`nan`、`infinite` 创建对应类型的空实例。
- **true / false**：创建 `boolean` 实例，`true` 存储值 1，`false` 存储值 0。

### 标识符（变量名）

在当前作用域解析这个名字，拿到地址后从地址空间取出值返回。

### 代码块

把代码块中的语句列表与定义时所在的作用域打包成代码块值返回。不会立即执行，要等到被调用时才执行。

### 列表字面量 `[a, b, c]`

遍历各项，逐个求值并把值存入链表节点，维护头尾指针构成单向链表；至少一个元素时把头尾节点存入链表实例，返回链表实例。

### 一元运算符

- **`~`**：在父作用域中求值操作数（用于跨越一层作用域访问）；没有上级作用域时报错。
- **`*` 声明**：如果操作数是名字且当前作用域还没有这个变量，分配新地址并声明；已有则返回当前值。
- **`/` 取地址**：操作数必须是名字，返回该名字对应地址的地址值。
- **`**` 引用声明**：把操作数名字的地址包装成地址值存入新存储单元，再用这个名字声明指向它。此后两个名字共享同一存储，任一变、另一个同步变。
- **`***` 常量声明**：操作数是名字则分配新地址并标记常量后声明；是 `类型.成员` 则在类型对象上创建新成员并标记常量，若该成员已存在则报错"常量成员已存在"。
- **`!`**：对操作数取反（用真值判定）。
- **`+` / `-`（一元）**：对操作数取正/负，作用于数值类操作数（整数、数字等）。
- **`*` 解引用**：操作数必须是地址值，取出其内部地址并从地址空间读取值。
- **`$` / `return`**：返回，携带操作数的值。
- **`<-`**：报错，携带操作数的值。
- **`??`**：注解读取。操作数必须是名字，从运行时的注解表中取出该名字的[注解](../../Tanex%20Script%20文档/注解.md)内容，构建成字符串返回；该名字没有注解则返回 `none`。

### 二元运算符

大部分运算符先求值左右操作数。特殊处理以下运算符：

- **`=>`**：构造匿名函数。从左侧列表提取参数名与默认值，求值右侧得到代码块值，把参数信息植入后返回。
- **`$$`**：循环符。反复求值左操作数作为循环条件，条件为真时求值右操作数作为循环体，直到条件为假或遇到 `break` 跳出。循环中 `{$ 表达式;}` 的值会被收集，结束后以列表类型实例返回收集到的值（如 `['1', '2', ..., '10']`）。
- **`<<`**：输出。右操作数必须是注册了 `string` 特殊成员的对象，调用该成员得到字符码链表，交给左操作数（处理函数）处理，再遍历链表把每个字符码转成字符输出。右操作数不满足则报错，提示缺少 `string` 特殊成员。
- **`>>`**：输入。与 `<<` 对称：读取输入得到字符串，左操作数（处理函数）处理输入，结果填入右操作数（地址）。
- **其它**：整数对整数直接用数值运算；否则查找左操作数类型上注册的对应方法并调用。见[运算符方法映射](#运算符方法映射机制)。

### 赋值

1. 解析左侧赋值目标得到地址。
2. 求值右侧表达式。
3. 普通赋值 `=`：把值写入地址。若左侧是 `***` 声明或 `类型.xxx` 形式，额外处理：
   - `*** 名字`：标记地址为常量。
   - `*** 类型.init`：设置类型的构造器。
   - `*** 类型.boolean`：设置布尔转换特殊成员。
   - `*** 类型.string`：设置字符串转换特殊成员。
   - `*** 类型.index`：设置索引特殊成员。
   - `*** 类型.addition / subtract / multiply / divide / exactly_divisible / modulo / power`：设置对应算术特殊成员。
   - `*** 类型.positive / negative`：设置一元正负号 `+n` / `-n` 特殊成员。
   - `*** 类型.greater / less / greater_equal / less_equal / equal / not_equal`：设置对应比较特殊成员，见[比较特殊成员](../../Tanex%20Script%20文档/特殊变量.md#比较特殊成员)。
   - `*** 类型.compare`：设置三路比较特殊成员，作为比较运算符的最后兜底，见[compare 三路比较特殊成员](../../Tanex%20Script%20文档/特殊变量.md#compare--三路比较特殊成员)。
   - `类型.inherit`：设置继承目标，并把父类型的所有成员全量复制给子类型。见[继承机制](#成员查找与继承机制)。
4. 复合赋值（`+=` `-=` 等）：先从地址读出旧值，执行对应运算得到新值，再写回地址。

### 类型构造 `类型{...}`

1. 求值类型表达式拿到类型对象。
2. 创建该类型的一个新实例。
3. 逐个求值包含的参数。
4. 如果有构造器，调用构造器并传入参数。

**机制**：构造器指类型定义里注册的 `init` 方法（`*** 类型.init` 或继承自父类型的 `init`）。`type_type` 自身的通用构造器只用于定义新类型（`type_type{...}`），不视为用户类型的构造器。因此一个没有定义 `init` 的类型，空参构造 `mt{}` 正常创建实例；带参构造 `mt{值}` 会报错"类型没有定义 init 构造器，不能传参构造"。

**机制补充**：

- 类型对象被当作函数调用（`类型(...)`）时，等价于构造。
- `type_type{}` 用于定义新类型，返回一个全新的裸类型对象。
- `number{front, back}` 双参形式走快捷构造，直接按整数部分/小数部分组装，供算术运算内部使用。
- `none_type{...}` 构造一律返回共享的 `none`。

### 函数调用

1. 求值函数名表达式拿到可调用对象（函数或类型）。
2. 逐个求值参数，把每个参数存入地址空间，传地址而不是传值。
3. 成员形式的调用（`a.b(...)`）额外把左边的对象作为第一个实参传入。
4. 基于代码块定义时所在的作用域建立新子作用域。
5. 把参数名和传入的参数地址一一绑定到新作用域。
6. 缺省参数：参数个数到参数名总数之间的参数用默认值求值补齐，无默认值的补为 `none`。
7. 依次执行函数内的每条语句。
8. 执行中捕获到返回则返回其携带的值，否则返回最后一条语句的值。

**机制**：参数传地址而非传值，是引用语义的基础——函数内对参数赋值能直接影响调用方的变量。成员函数调用时自动把调用对象作为第一个实参传入，因此该参数的命名由定义者决定（习惯上叫 self），用它即可读写调用对象的成员。

### 下标访问 `a[b]`

1. 求值左右表达式。
2. 左边是实例、且类型注册了索引方法：调用索引方法（传左值与右值的地址），返回值的取法按结果类型分三种：
   - 结果是地址值：读取该地址里的值返回。
   - 结果是带 `value` 成员的实例：返回该成员的值。
   - 其它结果：直接作为下标访问的结果返回。
3. 左边是实例、没有索引方法但类型注册了构造器：调用构造器（以右值为参数）作为取下标的结果。
4. 以上都不满足：报错"类型不支持下标操作"。

### 成员访问 `a.b`

1. 求值左边的表达式。
2. 实例：先在实例成员里找，找不到到类型成员里找，再找不到沿继承链找。
3. 类型：在类型成员里找，找不到沿继承链找。
4. 都找不到时报"成员不存在"。

### 三目运算符 `a ? b : c`

用真值判定判断条件：真返回 `b` 分支，假返回 `c` 分支。

### 尝试结构 `left | *err : catch : else`

1. 尝试执行左操作数。
2. 成功则执行 else 块（如果有）。
3. 出错则把错误值绑定到 `*err`，执行 catch 块。错误值的来源：`<-` 抛出的值、运行时错误的信息、其它错误的信息。

**机制**：`|` 是唯一能拦截报错的结构。捕获到的错误值会被绑定到 `*err` 声明的名字上（若已存在同名变量则覆盖其值），供 catch 块读取。`error` 类型的 `what` 成员、`throw()` 方法等错误处理能力都建立在这一机制之上。

## 专项机制

### 成员查找与继承机制

成员查找统一遵循"实例成员 → 类型成员 → 继承链"的顺序，沿 `inherit` 指针逐层向上找。

当执行 `子类型.inherit = 父类型` 时，解释器除了设置继承指针，还会把父类型的所有成员**全量复制**到子类型的成员字典（跳过 `addable`、`external_read_only`、`inherit` 等特殊变量，见[特殊变量](../../Tanex%20Script%20文档/特殊变量.md)）。因此子类型既继承了父类型的成员，也可以覆盖或新增成员。

### 运算符方法映射机制

引导库为类型注册的算术特殊成员与比较特殊成员，分别与对应的运算符一一对应，再从左操作数的类型上查找：

| 运算符 | 特殊成员 |
| ------ | -------- |
| `+` | addition |
| `-` | subtract |
| `*` | multiply |
| `/` | divide |
| `\` | exactly_divisible |
| `%` | modulo |
| `^` | power |
| `>` | greater |
| `<` | less |
| `>=` | greater_equal（由 `less` 兜底取反） |
| `<=` | less_equal（由 `greater` 兜底取反） |
| `==` | equal |
| `!=` | not_equal |

**机制**：先在类型（含继承链）的成员里找对应方法，找不到再回退到特殊成员槽位。这样既支持 `*** 类型.addition = 函数` 把方法注册进槽位，也支持把方法以普通成员的形式放进成员字典。

比较运算符 `>`、`<`、`>=`、`<=`、`==`、`!=` 对应的特殊成员 `greater`、`less`、`greater_equal`、`less_equal`、`equal`、`not_equal` 之间**不相互派生**——类型内部不需要写出 `!(less() && equal())` 之类的组合。当运算符对应的特殊成员未定义时，由解释器在**函数调用层**以"兜底调用"补齐：调用相关特殊成员时，给控制函数调用的方法附加一个参数，标记"本次调用是给另一个方法兜底的"，由解释器据此组合结果：

- `greater` 未定义 → 兜底调用 `less` 与 `equal`，结果取反组合（`!(less || equal)`）。
- `less` 未定义 → 兜底调用 `greater` 与 `equal`，结果取反组合。
- `greater_equal`（`>=`）未定义 → 兜底调用 `less`，结果取反（`!less`）。
- `less_equal`（`<=`）未定义 → 兜底调用 `greater`，结果取反（`!greater`）。
- `equal` 未定义 → 兜底调用 `not_equal`，结果取反。
- `not_equal` 未定义 → 兜底调用 `equal`，结果取反。

被兜底调用的方法通过调用参数上的标记知道自己处于兜底场景，避免无限递归；因此类型只定义 `less` 与 `equal`，即可获得全部比较能力。见[比较特殊成员](../../Tanex%20Script%20文档/特殊变量.md#比较特殊成员)。整数上的比较直接做数值比较。

**`compare` 与对象同一性兜底**：当某比较运算符的直接特殊成员未定义，且组合兜底所需的其他特殊成员也缺失时，解释器尝试类型上的 `compare` 三路比较特殊成员：调用它得到一个 `integer` 或 `number`，按符号判断结果（负数=小于、零=等于、正数=大于），再按运算符转成布尔。`compare` 返回值不是 `integer`/`number` 时直接报错。若类型也没有 `compare`，则落入[对象同一性兜底](../../Tanex%20Script%20文档/特殊变量.md#对象同一性兜底)：`==`、`!=`、`<=`、`>=` 按是否为同一个对象判断，`<`、`>` 恒为假，不再报错。`type_type` 不再内置 `equal` 特殊成员。

**一元正负号**：一元 `+n`、`-n` 在操作数是用户类型实例时，分别查找类型上的 `positive`、`negative` 特殊成员并调用；缺失时内置数值类型（`number`、`infinite_type`、`nan_type`）保持内置行为，其他类型报错。见[positive / negative —— 一元正负号特殊成员](../../Tanex%20Script%20文档/特殊变量.md#positive--negative--一元正负号特殊成员)。

### 循环收集机制（`$$`）

`$$` 循环以左操作数为条件、右操作数为循环体：条件为真时执行一次循环体，然后重新求值条件，直到条件为假或遇到 `break` 才退出。循环体内 `$ 表达式` 的语义从"返回"临时变成"收集"——其值被追加进收集列表，而不是作为返回。循环结束后收集到的值以列表类型实例承载返回。

**条件的求值形式**（按左操作数类型分）：

1. 实例且类型注册了构造器：调用构造器（以实例自身为参数），把返回值当真值判断。
2. 实例但类型无构造器：直接视为假，立即退出。
3. 代码块：作为条件函数执行，结果当真值判断。
4. 其它值：直接用真值判定规则判断。

**循环体执行**：求值右操作数；若结果是代码块值，就以代码块方式执行。执行中抛出 `break` 信号会立即退出循环。

**机制**：这就是"循环返回结果"的实现。`$$` 通过临时改写 `$` 的行为，让循环可以边执行边收集每轮的结果，最终得到完整的结果列表。

### 匿名函数参数解析机制（`=>`）

`=>` 构造匿名函数时从左侧参数列表直接提取参数信息，不做求值。支持三种写法：

- `name`：普通参数名。
- `*name`：按地址传参的参数。
- `[*name, 类型, 默认值]`：带类型约束和默认值的参数；默认值以 AST 形式暂存，调用时才求值。

提取出的参数名列表与默认值列表被写入右侧代码块，之后该代码块可被当作函数调用。

### 存在判断机制（`in`）

`a in b`：如果右操作数 `b` 的类型注册了 `index` 特殊成员，就对 `b` 进行遍历，每轮取出当前位置的元素与左操作数 `a` 比较；一旦 `a == 元素`，`in` 表达式返回真；遍历完仍未找到则返回假。若 `b` 的类型没有 `index` 特殊成员，则报错。

**机制**：`in` 的存在判断建立在右操作数的可索引性上——`b` 需要提供 `index` 特殊成员（如链表、字符串），解释器逐位调用它取出元素与左操作数 `a` 比较，直到相等或遍历结束。
