# main — 运行时入口

负责启动运行时环境、加载引导库、执行用户代码。

---

## 启动流程总览

1. 建立地址空间与全局作用域。
2. 初始化内置核心类型。
3. 定位并加载引导库 `bootstrap.tscc`。
4. 执行用户 `.tscc` 文件。

前两步建立"骨架"，第三步把引导库里的方法与成员填进骨架，第四步在完整环境下运行用户代码。

---

## 引导文件定位

启动时在 `run/` 目录下查找 `bootstrap.tscc`（编译后的引导库文件）。只检查这一个路径，找不到就跳过引导阶段。

**机制**：引导文件以编译后的形式分发，运行时不再进行词法/语法分析，直接加载 AST 执行，因此启动很快。

---

## 全局类型初始化

在加载任何用户代码之前，先在地址空间中创建语言的内置核心类型：

### 类型基

创建基类型 `type_type` 的实例，存入地址空间并标记为常量。这个类型对象是所有其他类型的模板，在全局作用域中注册名字。

### 原类型

创建一个独立的类型实例，同样存入地址空间并标记常量。整数类型是特殊的——它由解释器内部注册，整数值在运行时直接以整数形式存在，不包装为实例对象。

### 其他核心类型占位

依次创建以下类型的空实例（有类型对象但没有成员和方法）：

- 字符串、数字、布尔、空类型、NaN 类型、无穷类型、链表、代码、地址、错误、警告

这些类型在引导库执行时会被填充具体的方法和成员。`true` / `false` 常量则由引导库定义（见[引导库布尔常量](bootstrap.md#常量)），不属于启动阶段的占位内容。

**机制**：核心类型必须先于引导库存在，因为引导库代码本身就引用 `type_type{}`、`boolean`、`number`、`none` 等名字。先建"空壳类型"，再让引导库往里填方法，是"先有骨架、后有血肉"的启动顺序。所有核心类型都标记为常量，防止用户代码无意中篡改。

---

## 引导阶段

1. 打开 `bootstrap.tscc`。
2. 解析出 AST 语句列表。
3. 在初始化好的全局环境中逐条执行引导语句。
4. 执行完成后，所有核心类型的方法、辅助函数、常量都已注册到环境中。

这个阶段相当于在运行用户代码前先运行一遍内置环境库。若引导文件带有 `annotations` 字段（编译期记录的[注解](../../Tanex%20Script%20文档/注解.md)），会一并合并进解释器的注解表，供 `?? n` 读取。

---

## 用户代码执行

1. 接收命令行传入的 `.tscc` 文件路径。
2. 检查文件是否存在，不存在则报错退出。
3. 打开文件，解析出 AST 语句列表。
4. 在同一个地址空间和全局作用域中（引导阶段已经设置好环境）执行用户语句。
5. 处理执行过程中出现的情况：
   - 顶层显式 `$`/`return`：返回整数时以该值作为程序退出码退出；返回非整数时报错。
   - 报错：打印程序报错信息。
   - 其它错误：报错提示运行时错误。
   - 正常结束（无顶层返回）：不输出任何额外内容，进程以退出码 0 结束。

用户文件编译结果中的 `annotations` 字段同样会合并进注解表，与引导阶段收集的注解共存。

**机制**：用户代码与引导库共享同一地址空间和全局作用域，因此用户代码可以直接使用引导库定义的全部类型、函数与常量；引导阶段的注册内容对用户是"天然存在的环境"。
