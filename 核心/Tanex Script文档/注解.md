# 注解

注解是[注释](注释.md)的变种。与注释不同，注解不会被编译器完全忽略：注解会把一段说明文字与目标关联起来，供程序在运行时通过[注解运算符](运算符.md)（`??`）读取。

## 语法

`@ {标识符} # ***** #;`

注解以 `@` 开始，以 `#;` 结束。`@` 与 `#` 之间为目标标识符，`#` 与 `#;` 之间为注解内容。标识符可省略：省略标识符时表示**文件级注解**，即给整个文件/库写注解。

## 示例

给标识符 `for` 写注解：

```tanex script
@ for #
可以遍历一个可遍历值，每遍历一次执行一次操作。
#;
```

上面的注解会把标识符 `for` 注解为"可以遍历一个可遍历值，每遍历一次执行一次操作。"

给整个文件/库写注解（无标识符）：

```tanex script
@ # 这是标准库 #;
```

库被 `import` 后，`?? 导入标识符` 会返回该文件级注解文本。

支持成员级注解（`类型.成员` 形式）：

```tanex script
@ boolean.addition # 布尔值相加，返回整数（真=1、假=0） #;
```

## 编译后表示

注解在词法分析阶段被识别为 `token`，在语法分析阶段被解析并记录到编译结果的 `annotations` 字段中，**不加入最终AST语句列表**。

编译结果中 `annotations` 是一个以目标标识符为键、注解内容为值的映射：

```json
{
    "Tanex Script": [],
    "annotations": {
        "for": "可以遍历一个可遍历值，每遍历一次执行一次操作。"
    }
}
```

存在文件级注解时，编译结果顶层还会额外出现 `annotation` 字段，以字符串形式保存文件注解内容：

```json
{
    "Tanex Script": [],
    "annotations": {},
    "annotation": "这是标准库"
}
```

## 读取注解

注解读取**有作用域**，使用一元运算符 `??`：

- `?? n` 读取**当前文件/顶层作用域**中标识符 `n` 的注解（含文件注解与库文件级注解）；查不到则报错「注解不存在」
- `?? lib.member` 读取已导入库 `lib` 独立注解空间中 `member` 的注解（`member` 可以是该库的任意标识符或成员级注解，如 `?? standard.for`）
- `?? type.member` 读取当前作用域中的成员级注解（key 为 `"type.member"`，如 `?? boolean.addition`）

示例：

```tanex script
import "standard" = standard;
standard_output << ??standard.for;   # standard 库中 for 的注解
standard_output << ??boolean;        # 顶层 bootstrap 的 boolean 注解
```

导入库时，库的注解会写入该库**独立的注解空间**，不会平铺进顶层：顶层 `?? for` 在未定义时会报错，必须通过 `?? standard.for` 访问。
