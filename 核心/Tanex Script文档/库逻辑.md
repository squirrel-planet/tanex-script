# 库逻辑

每个 Tanex Script 库都应该有一定的限制，保证用户可以正确引入。

## 防止歧义

当一个库中有多个同名内容时(如同时有 main.tsuc main.tscc main/ main.tscl)，报错，说明不能有多个同样的内容，避免歧义。

## 如何编译库？

编译一个库，应该把库内的文件一个一个写人编译后的文件：

```文件格式
# 编译 lib 文件夹为 lib.tscl
lib/
  main.tsuc
  type.tsuc
  init/
    main.tsuc
    init.tsuc
```

应该以二进制写入：

```tscl
{
  "/main.tscc": ..., // 应该把main.tsuc编译后再写入，值为main.tscc的编译后内容
  "/type.tscc": ...,
  "/init/main.tscc": ...,
  "/init/init.tscc": ...
}
```

## main 主内容 逻辑

每个库在没编译前的文件夹里都可以有一个主内容，以 `main` 命名。
没有主内容，不会报错，但需要用户手动引入库中需要的内容(这种需要手动引用的库，或许并不会让用户喜欢)。

当出现以下情况时：

```文件格式
# 用户引入 "lib" 库
lib/
  main/          # main 文件夹下还有 main 文件夹
    main/        # main 文件夹下有 main.tsuc
      main.tsuc
      other.tsuc
    other.tsuc
  other/
    main.tsuc
```

那么实际应该引入 `lib/main/main/main.tsuc` (最深层的主内容)

当库中包含了其他的已编译库时，不应该让该已编译库直接写入编译后的文件，而是把内部的文件重新写入编译后的文件。

如：

```文件格式
lib/
  main.tsuc
  other.tscl/    # 这里只是展示内部结构，实际上是二进制内容
    main.tscc
    init.tscc
```

编译后应该为:

```tscl
{
  "/main.tscc": ...,
  "/other/main.tscc": ...,
  "/other/init.tscc": ...
}
```

而不是：

```tscl
{
  "/main.tscc": ...,
  "/other.tscl": ...
}
```
