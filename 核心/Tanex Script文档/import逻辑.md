# import 逻辑

`import`(`->`)用于引入Tanex Script文件(.tsuc)、Tanex Script已编译文件(.tscc)、文件夹(Tanex Script库格式的文件夹)或Tanex Script库(.tscl)。

`import` 与 `->` 都是**表达式符号**（Pratt 前缀运算符）：解析阶段按前缀运算符处理，操作数是**任意表达式**，运行时先对操作数求值得到字符串路径，再加载对应内容。它们不是普通的一元/二元运算符，不能作为中缀使用。二者语义不同：`import` 将目标打包为 `library` 并通过命名句柄访问；`->` 将目标文件所有内容直接展开到当前作用域（详见下文）。

AST 分别表示为：

```json
{"import": {"path": <表达式AST节点>, "name": <标识符字符串或null，列表命名时可为标识符列表>, "by_ref": <bool或null，列表命名时可为bool列表>, "pos": [l,c]}}
{"include": {"path": <表达式AST节点>, "pos": [l,c]}}
```

`path` 字段从字符串字面量改为**表达式节点**。静态字符串字面量会在预编译阶段解析为绝对路径（保留原有预编译依赖逻辑）；任意表达式（字符串拼接、变量、函数调用等）运行时求值后再加载。

`import` 引入一个内容时，会把它的名字处理为一个 Tanex Script 标识符，然后把一个 `library` 类型的值填入该标识符（该标识符为**常量**，不可再赋值），值内部存储导入的内容。

`import` 的库内容**不会**被展开到全局作用域，只能通过该 `library` 句柄访问，如 `standard.output(...)`、`standard.type()`；直接使用 `output(...)`、`type()` 会因"变量未定义"报错。

库的**注解**同样隔离：`import` 时写入该库独立的注解空间，读取需通过 `?? 库.成员`（如 `?? standard.for`），不会平铺进顶层注解表。

引用 `"standard"` 时，自动引用标准库。

## 两种形式

### 单条引入

`import "s" + "tandard";`、`-> "code" + ".tsuc";`

操作数为任意表达式，运行时求值得到字符串路径。静态字符串字面量（如 `import "standard";`）在预编译阶段解析为绝对路径并写入 AST；动态表达式（拼接、变量等）原样保留，运行时求值。

`->` 与 `import` 的单文件形式都合法，但语义不同：`import` 打包为 `library` 句柄；`->` 把该文件的所有顶层声明直接展开到当前作用域，不生成句柄。

### 命名引入

`import expr = *name;`

把一个内容引入，并把内容**传地址（引用绑定）**存储进规定的标识符 `name` 里。`=` 后必须是 `*` 前缀加静态标识符（不可用表达式），`*` 表示该标识符直接引用库实例本身（共享同一对象，通过任一引用对库成员的改动互相可见）。

命名引入右值只能是地址引用：`import expr = name;`（不带 `*`）不是合法写法，解析时直接报错并提示改用地址引用（要么提前声明变量后取地址 `import expr = *std;`，要么直接写 `import expr = *name;`）。名称列表同理，每个元素都必须是带 `*` 前缀的静态标识符，裸标识符元素（`[n1, n2]`）直接报错。

解析时 `=` 不会被当作 import 操作数的一部分消费（操作数以赋值优先级之上的右绑定解析），遇到 `=` 后解析 `*` 前缀与标识符作为 `name`（`by_ref` 标记写入 AST）。

`->` 不支持命名引入：`-> expr = name;` / `-> expr = *name;` 均报错；如需命名引入请使用 `import` 关键字。

例如：

- `import "lib.tsuc" = *mylib;`：引入 `lib.tsuc`，把内容引用绑定到 `mylib`。
- `import "lib_" + suffix = *mylib;`：路径为运行时求值结果。

## 列表批量引入

可以在一条语句中引入多个内容：

- `import [expr1, expr2];`：分别引入各表达式求值得到的路径，默认以路径名为标识符。
- `import [expr1, expr2] = [*n1, *n2];`：引入并分别**传地址（引用绑定）**进 `n1`、`n2` 标识符（元素带 `*` 前缀表示引用绑定，裸标识符元素直接报错）。

列表元素可为任意表达式，运行时求值；路径列表与名称列表（若存在）的长度必须一致，否则报错；路径列表不能为空。

要求：

- 路径列表与名称列表（若存在）的长度必须一致，否则报错。
- 路径列表不能为空。
- 路径列表的每个元素求值后必须是字符串文件路径；名称列表的每个元素必须是带 `*` 前缀的标识符（地址引用绑定）。
- 同一路径同一名称只导入一次；同一路径不同名称（如重复引入同一内容）允许，运行时复用已加载的内容。
- `->` 同样支持列表引入多个文件，语义为依次把每个文件的所有内容展开到当前作用域；`->` 不支持列表命名（`= [...]`），如需命名引入请使用 `import`。

## 预编译阶段与动态加载

- 若操作数是**静态字符串字面量**（单条或列表中的元素），预编译器保留原有依赖收集与编译逻辑：解析路径、把 `.tsuc` 编译为 `.tscc`、写回绝对路径。
- 若操作数是**任意表达式**（拼接、变量等），预编译器保留 import token 序列原样输出、不静态解析依赖，由运行时在求值后动态加载（复用 `_load_library_module` 与标准库解析逻辑）。

有一些引用的情况需要考虑：

1. 引入 "lib"，但工作目录下有多个匹配"lib"的可引用内容(如 ./lib/ ./lib.tsuc ./lib.tscc ./lib.tscl)。
解决方法: 报错，说明若有多个可引用的内容，可以加后缀避免歧义(文件夹加`/`，文件加后缀名)，也可以直接写绝对路径。
编译产物不算独立内容，不会触发歧义: `.tscc` 是同名 `.tsuc` 的编译产物，`.tscl` 是同名文件夹的编译产物。
同名文件夹与 `.tscl` 同时存在时，裸名导入 `.tscl`；要导入文件夹，需加 `/` 后缀(如 `"lib/"`)。

2. 类似(1)的情况，引入"standard"，但同时有多个可引用内容，可以引用标准库，可以引用工作目录下的内容，报错提示需要绝对路径(标准库在 Tanex Script 安装目录下)。

3. 引入内容后发现有同样标识符的内容，就覆盖它，然后给予警告。

4. 如果引入的内容包含多个相同标识符的内容(如，用户尝试引入lib，但 lib/ 里同时有 a.tscc, a.tsuc 两个同样的内容，引入后会变为两个相同标识符的 a)，报错。

5. 若导入内容的名字是一个不可转标识符的内容，报错，提示要命名引入 `import expr = *name;`。

## REPL 下的内置填充常量

REPL 会话与脚本运行一样会注入内置填充常量：`path`、`program_path`、`args` 等。REPL 模式下这些常量同样允许填充，其中：

- `path`：填充为 `none`（REPL 没有当前脚本路径）；
- `program_path`：保持常规解析值（按解释器安装目录解析）；
- `args`：照常填充（命令行参数，REPL 下通常为空）。

因此在 REPL 中也可以安全使用 `import "{program_path}/..."` 这类基于内置常量的路径引入，不会因常量未定义而报错。
